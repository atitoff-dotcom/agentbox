# 🗺️ AgentBox Roadmap & RFC

В этом файле фиксируются согласованные архитектурные решения, концепции и задачи для будущей реализации.

---

## 📌 RFC: Строгая изоляция Python в `.agentbox/venv` (Hermetic Environment)

### 1. Цель и концепция
Обеспечить абсолютную изоляцию и предсказуемость исполнения Python-кода как на удаленном сервере (по SSH), так и на локальной машине:
* Все команды и тесты, запускаемые через AgentBox, должны выполняться **исключительно** внутри окружения `.agentbox/venv`.
* **Агент физически не должен иметь возможности вызывать Python откуда-либо, кроме `.agentbox/venv`.**
* Системный интерпретатор сервера и любые внешние виртуальные окружения полностью изолируются и не могут быть случайно затронуты агентом.

---

### 2. Алгоритм работы (Lifecycle)

При каждом вызове команд выполнения (`agentbox run`, `agentbox test`, `agentbox spawn`):

1. **Проверка существующего окружения:**
   * Сначала проверяется наличие директории `<work_dir>/.agentbox/venv`. Если найдено и валидно — используется оно.
   * Если нет — проверяется директория `<work_dir>/.agentbox` (на случай плоского venv). Если валидно — используется оно.
2. **Автоматическая установка (Auto-bootstrap):**
   * Если окружения нет ни в одном из указанных мест, AgentBox **автоматически создает** его перед запуском команды:
     ```bash
     python -m venv <work_dir>/.agentbox/venv
     ```
   * Создание происходит прозрачно и на лету (и на локальной машине, и на удаленном сервере через worker).
3. **Санитизация и изоляция окружения (Environment Sanitization):**
   * Переменная `PATH` модифицируется так, чтобы путь к бинарникам venv (`<work_dir>/.agentbox/venv/bin` на Linux/macOS или `Scripts` на Windows) стоял строго на первом месте.
   * Переменная `VIRTUAL_ENV` указывает строго на `.agentbox/venv`.
   * Переменная `PYTHONHOME` принудительно удаляется.
   * Из `PATH` исключаются пути к чужим виртуальным окружениям.
4. **Блокировка прямых системных вызовов:**
   * Если переданная команда пытается напрямую вызвать системный интерпретатор (например, `/usr/bin/python3`, `/usr/bin/python`, системный `python.exe`), команда перехватывается:
     * либо путь автоматически подменяется на `.agentbox/venv/bin/python`;
     * либо возвращается блокирующая ошибка с пояснением.

---

### 3. Установка пакетов (pip) и опциональные зависимости
* Любые пакеты, устанавливаемые агентом (`agentbox run "pip install <pkg>"`), попадают строго в изолированный `.agentbox/venv`.
* В `ai-agentbox` можно предусмотреть команду-мост: `agentbox pip <args>`.
* Для расширения возможностей анализа (например, AST парсинг через `tree-sitter`):
  * Библиотеки оформляются как опциональные extras (`[project.optional-dependencies]`) с мягким импортом (`try ... import ... except ImportError`), сохраняя ядро AgentBox полностью zero-dependency.

---

### 4. Что потребуется изменить при реализации

1. **`src/agentbox/worker.py`**:
   * Обновить `find_virtualenv()`: сделать обязательный приоритет `.agentbox/venv`, затем `.agentbox`.
   * Добавить функцию `ensure_virtualenv(work_dir)`: автосоздание `venv` через `venv.create` / `subprocess.run([sys.executable, "-m", "venv", ...])`.
   * В `prepare_env_for_cmd()`: гарантировать вызов `ensure_virtualenv()` и жесткую санитизацию `PATH` и `VIRTUAL_ENV`.
   * Добавить перехват/подмену абсолютных путей к системному `python` в исполняемых командах.
2. **`src/agentbox/config.py`**:
   * Обновить шаблоны правил генерации (`init-rules`), добавив явное указание для агента в `AGENTS.md`, `.cursorrules`, `CLAUDE.md`: вызов Python разрешен исключительно через `.agentbox/venv`.
3. **`.gitignore`**:
   * Убедиться, что шаблон или генератор правил добавляет `.agentbox/venv` в `.gitignore` проекта.
4. **`tests/`**:
   * Добавить тесты на автосоздание `.agentbox/venv` при отсутствии и изоляцию `PATH`.
